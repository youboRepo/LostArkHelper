# 服务器版：邮件提醒、首次录入计划与用户管理

这些功能于 2026-11-09 加入服务器多用户版源码和网页构建。Windows、Linux 独立版与 iPhone 快捷指令本轮未改动，四端 v0.3.4 下载包保持原样；服务器使用最新源码部署时可使用本文功能。

## 1. 执行异常邮件提醒

管理员登录后进入「用户管理 → QQ 发信设置」，填写自己的 QQ 发件邮箱和 SMTP 授权码，勾选「启用 QQ 邮箱发信」并保存。

- 在 QQ 邮箱设置中开启 SMTP 服务，并生成授权码。填写的是 **SMTP 授权码，不是 QQ 密码或邮箱登录密码**。
- 当前固定通过 `smtp.qq.com:465` 使用 SSL 发送，支持 `qq.com` 和 `vip.qq.com` 发件地址；部署环境需能访问该地址。
- 授权码保存后不会回显。相同发件地址留空可保留原码，更换地址需填写该地址的授权码。
- 发信配置存于私有状态目录的 `mail-settings.json`，文件权限为 `0600`，已加入 Git 忽略规则；不得放入源码或发行包。

每位用户进入「账号管理 → 异常邮件提醒」，填写自己的收件邮箱、勾选「接收执行异常提醒」并保存。收件地址可使用其他邮箱服务，不限 QQ；默认关闭，管理员未启用发信时可先保存偏好。

定时执行或手动签到／领奖出现失败时，向已开启提醒的当前账号发送邮件，包括 token 无效、网络错误、提交后状态未确认等情形。成功、无可领奖任务、锁冲突跳过和只查询验证不会发信。邮件只包含账号名、执行记录编号、通知时间和安全的原因提示，不带 token、活动链接或官方接口原始响应。

每次失败记录最多尝试发信一次。QQ 认证失败、网络故障或管理员未配置发信时，保留游戏执行结果，在「运行记录」显示通知结果；不会因发信故障重复签到或领奖。同一问题若在下一次执行仍然失败，属于新的执行记录，会再次通知。当前没有自动补发旧记录的功能。

**验证范围：SMTP 使用模拟服务测试，尚未使用真实 QQ 邮箱发送邮件。** 填写真实邮箱及授权码后才具备实际发信条件。

## 2. 首次成功录入 token 后自动启用定时

新用户注册时尚无可用 token，不执行游戏任务。第一次活动链接通过登录校验且凭据保存成功后：

1. 为该用户随机选一个 `0–59` 的整数 N。
2. 自动开启「每小时第 N 分钟」执行，例如 N 为 37，即北京时间每小时的 `:37` 执行。
3. 导入成功提示告知选中的分钟，用户仍可在「定时设置」调整或暂停。

随机值只初始化一次。后续更新 token 保留已有计划，不重新随机，也不会重新打开用户暂停的任务。已有 token 的旧用户升级后更新 token，同样保留原计划。链接解析失败、登录验证失败或首次保存失败时不会启用计划。

本轮不修改调度服务的运行方式；服务器的 systemd timer 仍需正常运行，由每分钟检查选择到期账号。仅成功导入不会立即执行签到或领奖。

## 3. 管理员专用用户管理

原始 `ark` 初始化账号默认具有管理员权限。普通注册账号无管理员权限，不能通过注册参数授予自己权限。前端隐藏普通用户的「用户管理」入口，后端对管理员接口独立验证权限。

管理员可查看：

- 注册用户总数、用户名、注册时间及管理员身份。
- 是否录入 token。此状态表示凭据文件已存在，不表示 token 当前仍有效；列表不会向腾讯发请求验证。
- 定时任务是否启用及计划时间。
- 定时执行总次数、成功／失败次数；存在中断或执行中记录时另行展示。
- 最近一次定时执行时间和结果。

列表每页默认 30 人，支持刷新与翻页。统计包含已有的 `scheduled`／`scheduled_now` 执行记录，排除手动操作、只查询验证和跳过；待确认状态计入失败，中断与执行中单独计数。单个账号记录无法读取时显示「暂不可读取」。列表不返回密码、token、Cookie、授权码或接口原始响应。

如果未来需要把另一个**已注册账号**设为管理员，可在部署机器本地执行以下命令（需要额外授权时使用）：

```bash
python3 /opt/lostark-dashboard/service/manage_users.py \
  --root /var/lib/ark-dashboard \
  --admin 要授权的用户名
```

应由能访问私有状态目录的服务身份或管理员执行。授权后该用户重新登录或刷新网页即可看到入口。命令不会创建新账号，网页不提供公开的自助提权接口；本轮未增加封禁或重置密码功能。

### 删除账号

管理员可在「用户管理」列表的「操作」列点击「删除」。确认框显示目标账号及删除范围，必须输入完全一致的用户名，才能点击「确认删除账号」。可取消，或按 Escape 退出；删除请求发送期间等待返回结果。

- 删除账号的注册信息、全部登录会话、token、定时计划、运行记录、待确认记录和个人邮件提醒设置。操作无法撤销，不修改其他账号或全局 QQ 发信配置。
- 不能删除当前登录账号或系统初始 `ark` 账号；页面说明原因，后端也强制校验。
- 账号正在执行任务或处理其他操作时拒绝删除，提示等待结束后再试，避免在游戏请求中途移除数据。
- 已删除账号的旧会话立即失效，调度队列和已经取得旧身份的请求会在账号锁内重新检查，不能继续执行或重新创建私有数据。
- 新账号不复用已删除账号的数字 ID。允许重新注册相同用户名，但会成为独立的新账号，不能继承旧数据、权限或会话。
- 删除当前页最后一位用户后，列表自动回到前一页；删除失败保留确认框和原因，可取消或重试。

如果磁盘权限等原因导致部分文件无法清理，账号及会话仍会被撤销，定时任务停止；页面会明确提示私有目录 `users/<ID>` 需要管理员检查，不能把这类提示理解为数据已完全清理。账号锁文件保留在私有状态目录 `account-locks/` 中，只包含稳定的锁位置，不包含 token 或个人设置。已有的备份文件不会被此操作删除。

## 数据与本地验证

首次运行新版服务时原地扩展原有 SQLite 表，保留原账号密码、会话、token 和执行历史。增加管理员标记、个人收件偏好、首次录入标记、邮件投递状态及账号 ID 水位；发信配置另存私有文件。未来更新前仍需备份整个私有状态目录，并等待旧版任务执行结束后再替换代码。

本地验证使用临时数据库、模拟 SMTP 和模拟游戏接口，不操作真实游戏或线上数据：

```bash
python3 -m unittest discover -s server/tests -v
cd server/web
npx tsc -b
npm run build -- --outDir ../dist --emptyOutDir
```

另以桌面和手机视口检查管理员／普通用户入口、列表分页及错误重试、发信表单保存后清空授权码、个人提醒设置保存，以及删除确认、取消、失败重试、删除后列表刷新和末页恢复。网页预览使用虚构用户和执行记录，删除测试仅操作临时测试账号。
